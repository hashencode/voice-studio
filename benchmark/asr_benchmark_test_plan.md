# Paraformer ASR Benchmark Test Plan

This file defines the repeatable Paraformer benchmark layers. The benchmark compares parameter profiles, not model families. Models and raw run outputs stay under `build/asr_benchmark/` and are not committed.

Physical-device validation is part of the benchmark flow. A run may skip it only when the operator explicitly says emulator-only or no physical device is connected; record that reason with the result.

## Layers

| Layer | Source | Profiles | zh+en rows | Purpose | Commit policy |
| --- | --- | ---: | ---: | --- | --- |
| Smoke | `benchmark/asr_benchmark_profiles.json` | 4 default warm profiles | 8 | Fast validation that model assets, Android runner, reporting, and both routes work. | Commit. |
| Coarse | generated by `benchmark/generate_asr_profile_matrix.py --preset coarse` | 89 | 178 | Practical emulator sweep for the main interacting VAD and segmentation parameters. | Do not commit generated JSON; commit generator and report. |
| Full | generated by `benchmark/generate_asr_profile_matrix.py --preset full` | 4969 | 9938 | Large full-factorial grid for stable hardware or batch execution. | Do not commit generated JSON or raw results. |

The smoke layer is intentionally small. It must not be treated as exhaustive tuning evidence.

## Reproduce Coarse Run

Use the actual `adb devices` serial for `DEVICE_ID`.

```bash
./benchmark/download_asr_benchmark_models.sh \
  paraformer-zh-2025-10-07 \
  paraformer-en-2024-03-09

./benchmark/generate_asr_profile_matrix.py \
  --preset coarse \
  --output build/asr_benchmark/profile_matrices/paraformer-coarse-grid.json \
  --batch-size 30

BENCHMARK_PROFILES_FILE="$PWD/build/asr_benchmark/profile_matrices/paraformer-coarse-grid.json" \
  DEVICE_ID=emulator-5554 \
  ASR_BENCHMARK_TIMEOUT_SECONDS=10800 \
  ./benchmark/run_asr_benchmark.sh

latest="$(ls -t build/asr_benchmark/results/asr-benchmark-*.json | head -1)"
./benchmark/generate_asr_benchmark_visual_report.py --result-file "$latest"
```

Expected output:

- A raw result JSON under `build/asr_benchmark/results/`.
- `benchmark/asr_benchmark_summary_2026-07-05.json` regenerated from the selected result file.
- `benchmark/asr_benchmark_visual_report_2026-07-05.html` regenerated with standard and realtime replay tabs.
- 178 result rows and zero failures for the current coarse matrix.

## Execution Order

Run tests in this order:

| Step | Layer | Device | Command source | Purpose |
| --- | --- | --- | --- | --- |
| 1 | Static validation | local machine | JSON/shell/Python checks | Catch syntax and generator errors before using device time. |
| 2 | Smoke | emulator or physical device | `benchmark/asr_benchmark_profiles.json` | Verify model downloads, asset staging, Android runner, and report generation. |
| 3 | Coarse | emulator | generated `--preset coarse` matrix | Screen the main parameter interactions cheaply and repeatably. |
| 4 | Coarse winners | physical device | top profiles from coarse result or the full coarse matrix | Confirm actual device latency, memory, thermal behavior, and stability. |
| 5 | Full batches | physical device or stable lab emulator | generated `--preset full` batch files | Optional deep search after coarse winners are known. |
| 6 | Report | local machine | `generate_asr_benchmark_visual_report.py --result-file ...` | Generate a report for the selected run without mixing historical results. |

If time is limited, run smoke first, then coarse on emulator, then rerun only the top profiles on a physical device. Do not call the benchmark complete for production selection until physical-device evidence exists.

## Physical Device Run

List devices:

```bash
adb devices
```

Use the physical device serial, not `emulator-5554`:

```bash
BENCHMARK_PROFILES_FILE="$PWD/build/asr_benchmark/profile_matrices/paraformer-coarse-grid.json" \
  DEVICE_ID="<physical-device-serial>" \
  ASR_BENCHMARK_TIMEOUT_SECONDS=10800 \
  ./benchmark/run_asr_benchmark.sh
```

For a shorter physical-device confirmation, create a temporary profile file containing only the current winners and run that file with `BENCHMARK_PROFILES_FILE`. Keep the generated temporary file under `build/asr_benchmark/diagnostics/` so it is not committed.

## Reproduce Full Matrix

Generate the matrix and batch files:

```bash
./benchmark/generate_asr_profile_matrix.py \
  --preset full \
  --output build/asr_benchmark/profile_matrices/paraformer-full-grid.json \
  --batch-size 100
```

The full matrix should be run batch-by-batch. Do not start with the full single JSON on an emulator unless runtime and stability are acceptable.

Example batch run:

```bash
BENCHMARK_PROFILES_FILE="$PWD/build/asr_benchmark/profile_matrices/paraformer-full-grid/paraformer-full-grid-batch-001.json" \
  DEVICE_ID=emulator-5554 \
  ASR_BENCHMARK_TIMEOUT_SECONDS=10800 \
  ./benchmark/run_asr_benchmark.sh
```

After a batch run, generate a report from that batch result with `--result-file`. For a combined full analysis, either pass multiple `--result-file` arguments or add a dedicated merge step before interpreting winners.

## Ranking Rule

Rank only comparable rows:

- Compare warm rows with warm rows.
- Keep cold and current rows separate.
- Compare within the same route and language.
- Sort by error rate first, then operation RTF, then memory/segment behavior.

The current report follows this principle for top-line display. For final production decisions, rerun the winning profiles on physical devices.

## Git Policy

Commit:

- Benchmark source under `benchmark/`.
- Fixed audio fixtures under `benchmark/audio/`.
- Matrix generator script.
- Small generated report and summary when useful for review.
- This test plan.

Do not commit:

- `build/asr_benchmark/models/`
- `build/asr_benchmark/archives/`
- `build/asr_benchmark/results/`
- `build/asr_benchmark/profile_matrices/`
- device logs or staging files
