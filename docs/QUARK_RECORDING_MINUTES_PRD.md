## 1. 产品定位

夸克录音纪要是夸克体系内面向会议、采访、课堂、灵感记录等语音内容场景的 AI 听记工具。它把“录音 / 导入音频 / 导入视频”作为输入，把“原文转写、AI 总结、关键词、章节速览、翻译、播放回溯、导出分享”作为核心产出，帮助用户把非结构化音视频内容快速沉淀为可阅读、可编辑、可分发的文本资产。

从公开信息看，夸克整体定位为 AI 旗舰应用，提供搜索、助手与云端服务，并强调 AI 总结、文档处理、网盘多端同步等生产力能力。录音纪要应被视为夸克 AI 生产力与夸克网盘文件能力之间的连接型功能，而不是独立录音机。

## 2. 目标用户与场景

核心用户：

- 职场用户：会议记录、复盘、客户访谈、电话沟通整理。
- 内容工作者：采访录音、视频素材、播客 / 直播内容整理。
- 学生与学习用户：课堂、讲座、网课、学习视频转写与摘要。
- 轻量个人记录用户：语音备忘、灵感记录、生活记录。

高频场景：

- 会前打开“开始录音”，会后自动得到转写稿和纪要。
- 将本地或网盘中的音频 / 视频导入，生成可检索的文字稿。
- 阅读原文时按关键词、发言人、时间码、章节快速定位。
- 将纪要导出为 Word / PDF，或通过链接、微信、QQ、微博、钉钉等渠道分享。

## 3. 核心价值

1. 降低记录成本：用户不需要边听边手打，也不需要长时间反复回放。
2. 提高整理效率：AI 自动生成总结概要、关键词和章节速览，先给“可读版本”。
3. 支持回溯校验：转写文本与音频播放时间线绑定，用户可跳转、复听、修正。
4. 打通文件流转：支持导入本地 / 网盘音频，导出 Word、PDF、音频，支持链接分享。
5. 适配多人语音：通过“区分人声 / 讲话人”组织内容，适合会议、访谈等场景。
6. 强化录音中信号：通过热词、重点标记、批注和 P2 现场图片等人工信号，让 AI 摘要和待办更可验证。

## 5. 核心流程

### 5.1 新建录音纪要

1. 用户进入记录 Tab。
2. 选择“开始录音”“导入音频”“导入视频”或从系统分享面板导入。
3. 若为导入，选择本地、网盘或外部 App 分享过来的文件；公开教程显示 PC 端可从工具箱进入 AI 听记并导入本地音频或网盘音频。
4. 用户选择或系统识别音频语言，提交转写任务。
5. 系统进入“正在发起原文转写，请稍后查看”状态，内容区展示加载动画，播放器仍保留在底部。
6. 系统完成转写，生成原文、总结概要、关键词、章节速览和播放索引。
7. 用户进入详情页阅读、编辑、导出或分享。

### 5.2 列表内二次触发转写

1. 用户在记录 Tab 的统一记录列表看到未转写音频卡片。
2. 卡片右侧展示“AI转写”按钮，卡片内容只展示标题、时长、创建时间等基础信息。
3. 用户点击“AI转写”后进入转写发起流程。
4. 转写成功后，按钮状态变为“已转写”，卡片补充关键词和总结概要。
5. 若为示例内容，卡片展示“示例笔记”标识，避免与用户真实笔记混淆。

### 5.3 录音中辅助记录

1. 用户开始录音后，可在录音中设置录音语言、翻译语言和 AI 热词库。
2. 用户遇到重点结论、待办或疑问时，可点击重点标记，也可添加短批注。
3. P2 需要保留白板、合同、课件等现场上下文时，用户可拍照并绑定当前时间点。
4. 录音结束后，重点标记和批注进入同一条音频时间线，作为 AI 总结、待办提取和人工复核的依据；P2 图片遵循同一规则。
5. 若转写失败，录音中产生的标记和批注仍保留；P2 图片同样不得丢失。

### 5.4 阅读与复核纪要

1. 用户打开已转写笔记。
2. 默认进入“原文转写”或上次停留的 tab。
3. 用户可切换“总结概要”快速获取主要内容。
4. 用户可点击关键词筛选 / 定位，或使用搜索查找文本。
5. 用户通过底部播放器复听音频；通过时间码、发言人、章节速览、重点标记或 P2 图片时间线定位内容。

### 5.5 编辑与二次整理

1. 用户点击编辑图标进入编辑态。
2. 顶部显示取消、撤销、重做、完成。
3. 用户可编辑标题、关键词、讲稿文本、发言人、时间点、重点标记或批注。
4. 用户可触发 AI 整理，把口语化原文生成更适合阅读的语篇规整版本，但原文必须保留。
5. 完成后保存，详情页同步展示最新内容。

### 5.6 导出与分享

1. 用户点击导出 / 分享入口。
2. 导出支持 Word、PDF、音频；Word / PDF 可设置是否展示讲话人和时间码。
3. 分享支持微信好友、朋友圈、QQ 好友、QQ 空间、微博、钉钉、加密链接、公开链接。
4. 链接分享默认存在有效期提示，截图中为 30 天有效。

## 6. 功能需求

### FR-01 记录 Tab 入口

优先级：P0

- 展示页面标题“录音纪要”。
- P0 提供“开始录音”“导入音频”主入口；导入视频作为 P2 来源收进更多来源。
- P1 支持从系统分享面板进入导入流程，承接微信、QQ、录音机、文件管理器等外部来源。
- 记录 Tab 顶部保留搜索、处理中队列和可扩展的新建或快捷入口。
- 展示用户个性化标签或账号状态，例如截图中的“我只想开个网店”胶囊。

验收标准：

- 用户 1 次点击可进入录音或导入流程。
- “开始录音”视觉权重最高，“导入音频”作为次级入口，适配移动端单手操作。

### FR-02 统一记录列表与筛选

优先级：P0

- 默认展示“全部记录”。
- 支持筛选：全部、未转写、处理中、失败、已生成纪要。
- 记录卡片展示标题、时长、创建时间、状态、关键词、总结摘要。
- 未转写卡片右侧展示“AI转写”按钮，转写完成卡片右侧展示“已转写”状态。
- 已转写卡片展示关键词标签和“总结概要”预览；未转写卡片不展示摘要。
- 支持“AI转写”“已转写”“示例笔记”等状态或标识。
- 示例内容需展示“示例笔记”标识，例如会议类示例“开会用AI听记，5min整理关键纪要”。
- 顶部列表工具区包含 PC 入口和更多操作入口。
- P1 支持批量移动、批量删除和批量重试失败任务。

验收标准：

- 列表卡片能在 1 屏内传达“是否已转写、内容是什么、能否继续处理”。
- 筛选后列表内容与类型一致。

### FR-03 录音与导入

优先级：P0

- 支持直接开始录音。
- 支持导入本地音频。
- 支持导入视频并提取音轨转写。
- 支持从网盘文件导入。
- 支持通过系统分享面板从外部 App 导入音视频文件，作为 P1 能力。
- P0 需明确支持格式、最大时长、最大文件体积；建议先覆盖 MP3、WAV、M4A、AAC 等常见音频格式，视频和更长文件放入 P1/P2。
- 支持语言选择或语言自动识别；公开教程提到可选择音频语言后开始转文字。
- 提交后进入转写任务队列，列表显示进度或状态。
- 支持从列表未转写卡片直接点击“AI转写”触发转写。

验收标准：

- 导入失败时明确提示原因：格式不支持、文件过大、网络失败、权限不足、音频为空等。
- 同一文件重复提交或重复点击“AI转写”时，应复用已有任务或提示用户确认，不创建不可见的重复任务。
- 任务处理中用户可以离开页面，回到列表可继续查看状态。

### FR-04 原文转写

优先级：P0

- 详情页展示文件名、创建时间、音频时长。
- 原文按发言人、时间点分段展示。
- 发言人以圆形头像 / 缩写 + 名称 + 时间码展示；多人样例中可见“小K”“听记小助手”等不同发言人。
- 支持关键词展示、折叠 / 展开。
- 支持全文搜索。
- P1 支持按文件名、创建时间、来源、关键词和正文进行组合搜索。
- 支持复制、选择、编辑。
- 支持根据播放进度定位当前段落。
- 发起原文转写但结果未返回时，内容区展示加载动画与“正在发起原文转写，请稍后查看”文案。

验收标准：

- 每段转写至少包含文本；多人场景下包含发言人标识；可用时间码回放。
- 关键词点击后的定位或筛选行为明确。
- 原文加载状态不遮挡底部播放器，用户仍可播放原音频。

### FR-05 总结概要

优先级：P0

- 提供“总结概要”tab。
- 顶部展示一段整体摘要。
- 下方以项目符号展示结构化要点，每条包含加粗主题和说明。
- P1 支持 AI 整理：智能总结、待办提取、语篇规整和章节速览；P2 支持当前记录 / 全部记录两种范围的问答。
- 内容来自 AI 自动生成，必要时应提示可编辑或可能存在错误。

验收标准：

- 摘要可在 10 秒内帮助用户判断音频主题。
- 要点结构稳定，避免只生成长段落。

### FR-06 播放器

优先级：P0

- 底部固定播放器，展示当前进度和总时长。
- 支持播放 / 暂停。
- 支持前后 5 秒跳转。
- 支持播放设置入口。
- 播放进度与原文段落联动。

验收标准：

- 播放器在原文和总结 tab 下均可用。
- 拖动进度条后，文本定位和播放时间一致。

### FR-07 播放设置

优先级：P1

- 支持倍速：0.5x、0.8x、1.0x、1.5x、2.0x。
- 支持滑动刻度或按钮选择倍速。
- 支持“区分人声”开关。
- 设置以当前笔记或全局偏好保存，需产品明确。

验收标准：

- 倍速切换即时生效。
- 关闭“区分人声”后，转写展示和后续识别策略的影响需有说明。

### FR-08 章节速览

优先级：P1

- 提供“章节速览”入口。
- 底部弹层展示按时间点生成的章节卡片。
- 每个章节包含开始时间、章节标题、章节摘要。
- 支持展开 / 收起章节。
- 展示“内容由 AI 根据音频内容识别生成”提示。

验收标准：

- 点击章节时间可跳转到对应播放位置。
- 长音频可生成多个章节，并保持时间顺序。

### FR-09 编辑能力

优先级：P1

- 支持进入编辑态。
- 支持撤销 / 重做。
- 支持编辑标题。
- 支持删除关键词、添加关键词。
- 支持编辑转写文本。
- 支持保存或取消。

验收标准：

- 取消不保存本次修改。
- 完成保存后，原文、摘要、导出内容使用最新版本。

### FR-10 翻译

优先级：P1

- 在详情页提供“翻译”按钮。
- 支持对原文或总结进行翻译。
- 翻译状态应区分未翻译、翻译中、已翻译、失败。
- 翻译语言底部弹层展示“原文（不翻译）”和目标语言列表。
- 截图可见目标语言包括：英语、简体中文、繁体中文、俄语、日语、韩语、西班牙语；实际完整语言范围需以线上能力为准。
- 支持“双语显示”开关。
- 原文转写尚未完成时，翻译按钮应置灰或提示需等待转写完成。

验收标准：

- 用户能明确知道翻译对象是全文、选中片段还是当前 tab。
- 用户能明确知道当前选中的翻译语言，以及是否启用双语显示。

### FR-11 导出

优先级：P0

- 支持导出为 Word。
- 支持导出为 PDF。
- 支持导出音频。
- Word / PDF 导出支持设置讲话人、时间码是否展示。
- 导出入口需显示会员 / 限免 / 额度状态，截图中 Word 与 PDF 标记为“限免”。

验收标准：

- 导出文件内容与当前保存版本一致。
- 文件名默认沿用笔记标题，可编辑。
- 导出失败时给出可恢复路径。

### FR-12 分享

优先级：P0

- 支持微信好友、朋友圈、QQ 好友、QQ 空间、微博、钉钉。
- 支持加密链接和公开链接。
- 公开链接应提示有效期，截图中为 30 天。
- 底部展示合规提醒，禁止传播色情违法内容。

验收标准：

- 分享前用户能确认分享对象、访问范围和有效期。
- 加密链接与公开链接权限边界清晰。

### FR-13 搜索与关键词

优先级：P1

- 自动提取关键词。
- 关键词以标签形式展示。
- 支持折叠、展开、删除、添加。
- 搜索入口支持全文搜索，结果能跳转到对应段落。
- 搜索支持范围切换：当前记录 / 全部记录。
- 从记录详情发起搜索时，默认范围为当前记录。
- 从知识 Tab 发起搜索时，默认范围为全部记录。
- 全部记录搜索结果必须展示来源记录、命中片段和时间码；当前记录搜索结果直接定位到原文段落和音频时间。

验收标准：

- 搜索结果应高亮命中词。
- 用户能看清当前搜索范围，且可通过按钮菜单切换范围。
- 关键词删除后不再出现在展示和导出内容中，除非用户重新生成。

### FR-14 任务状态与异常

优先级：P0

- 状态包括：待上传、上传中、待转写、发起原文转写中、转写中、已转写、转写失败、导出中、导出失败。
- 对失败任务提供重试。
- 对长音频 / 大文件展示预计耗时或排队状态。
- 对无语音、噪音过大、语言不支持等结果低质量情况提供提示。
- 状态需同时覆盖列表态和详情态：列表可显示“AI转写 / 已转写”，详情可显示加载动画与转写提示文案。

验收标准：

- 用户能判断当前任务是否需要等待、重试或重新上传。

### FR-15 录音中辅助信号

优先级：P1

- 支持录音前或录音中配置 AI 热词库，用于提升专有名词、人名、产品名、行业术语识别效果。
- 支持录音中添加重点标记，标记必须绑定当前音频时间点。
- 支持录音中添加短批注，用于记录现场判断、疑问、结论或待确认事项。
- 支持拍照记录白板、课件、合同、票据等现场信息，图片作为 P2 能力进入时间线。
- 支持录音语言和翻译语言设置，后续转写、翻译和导出均继承该设置。

验收标准：

- 重点标记和批注必须绑定音频时间点，可在详情页回跳播放；图片进入 P2 后遵循同一规则。
- 热词库生效范围清晰：用户能知道热词作用于当前录音、本设备还是全局账号。
- 即使转写失败，录音中产生的标记和批注也必须保留；图片进入 P2 后同样不得丢失。
- P2 拍照需独立请求相机 / 相册权限，拒绝权限不影响录音继续。

### FR-16 AI 整理与语篇规整

优先级：P1

- 支持把口语化、重复、断句混乱的转写稿整理成更适合阅读的版本。
- 支持智能总结、待办提取和章节速览。
- P2 支持 AI 问答；从记录详情进入时默认针对当前记录，从知识 Tab 进入时默认针对全部已转写记录，用户可切换范围。
- 语篇规整结果必须保留与原文段落或时间码的关联。
- 用户可在原文、规整稿、总结和待办之间切换，不允许用规整稿覆盖原文。
- 用户可重新生成、局部接受或放弃 AI 整理结果。

验收标准：

- 语篇规整不得新增原音频中不存在的事实、结论、数字或承诺。
- 规整稿中的关键结论可回跳到原文和音频时间码。
- AI 问答进入 P2 后，只能基于当前选择范围回答；当前记录无依据时提示“当前纪要未提及”，全部记录无依据时提示“未在已转写记录中找到依据”。
- 用户放弃 AI 整理后，原文和已保存编辑不受影响。

### FR-17 文件管理与批量处理

优先级：P1

- 支持按来源、时间、状态、关键词搜索或筛选文件。
- 支持批量移动、批量删除、批量重试失败任务。
- 支持为历史记录或已生成纪要建立文件夹 / 标签，避免长期列表失控。
- 批量删除前需展示选中文件数量和不可逆提醒。
- 批量操作完成后展示成功数量、失败数量和失败原因。

验收标准：

- 未选择文件时，批量操作按钮置灰。
- 批量操作只能影响选中文件，不能误操作未选中文件。
- 批量删除必须同步处理转写、摘要、导出缓存和分享链接。
- 部分失败时保留成功结果，并允许用户查看失败清单或重试。

### FR-18 知识 Tab

优先级：P0 / P1 / P2

- P0 显示知识 Tab 空态和引导，说明“积累更多纪要后可在这里提问和整理”。
- P1 支持关键词搜索、搜索范围切换、主题聚合和收藏知识卡片。
- P2 支持 AI 问答、语义搜索、个人知识库和来源引用。
- 知识 Tab 默认搜索 / 问答范围为全部记录，用户可通过按钮菜单切换到指定记录。
- 从记录详情发起 AI 问答时，默认范围为当前记录，用户可切换到全部记录。
- 知识答案、知识卡片和主题结论必须能回跳到对应记录详情和时间码。

验收标准：

- 没有已转写记录时，知识 Tab 不显示空白页，而是引导用户录音或导入。
- 已转写记录不足时，提示继续积累，不强行展示低质量知识卡片。
- 用户能明确看到当前问答范围是“当前记录”还是“全部记录”。
- 当前记录问答没有来源时，提示“当前纪要未提及”；全部记录问答没有来源时，提示“未在已转写记录中找到依据”。
- 问答答案没有来源时，不展示为正式答案。

### FR-19 我的 Tab 与权益设置

优先级：P0 / P1 / P2

- P0 显示我的 Tab 基础壳：登录入口、用户信息占位、通用设置、隐私与数据、帮助反馈。
- P1 显示会员 / VIP、转写额度、导出权益、订单或兑换入口。
- P2 承接云同步、多端设备、硬件绑定、团队空间或企业权益入口。
- 我的 Tab 不承接录音、导入和知识问答主功能，只承接账号、权益和系统设置。

验收标准：

- 未登录用户仍可使用本地录音和本地记录；需要账号的能力给出登录引导。
- 额度不足时，记录页只做轻量提示，完整权益说明进入我的 Tab。
- 隐私与数据设置必须能解释本地优先、云端增强、导出分享、删除数据和清理缓存。

## 8. 体验规范

- 底部弹层：导出、分享、播放设置、章节速览均采用底部弹层，背景置灰，操作完成或取消后返回详情页。
- 详情页顶部：保留返回、编辑、导出 / 分享等高频操作，避免隐藏在多级菜单。
- 主色：以蓝色强调选中 tab、关键词、主按钮和进度点。
- 阅读排版：原文转写采用大字号、宽行距；总结概要采用段落 + 粗体要点，适合快速浏览。
- 发言人展示：多人内容使用不同颜色的圆形头像或缩写标识，名称与时间码使用弱化灰色，正文保持高可读性。
- 加载状态：内容区居中展示品牌色环形加载动画，文案使用弱化灰色；底部播放器固定可用。
- 列表状态：未转写卡片突出“AI转写”操作，已转写卡片弱化为“已转写”状态并展示摘要。
- 编辑态：顶部固定取消 / 撤销 / 重做 / 完成，降低误操作成本。
- AI 内容提示：章节速览和总结应在适当位置标注“AI 生成，仅供参考”或同等提示。

## 9. 权限、隐私与合规

- 录音前需请求麦克风权限。
- 导入本地文件需请求文件访问权限。
- P2 录音中拍照需请求相机 / 相册权限，拒绝后不影响录音和转写主流程。
- 系统分享导入需明确外部来源、临时文件读取权限和失败后的清理策略。
- 分享链接需明确公开范围、有效期、是否需要密码。
- 对录音转写内容应提供删除能力，并同步删除云端转写结果、导出缓存和分享链接。
- 分享面板需保留违法违规内容传播提醒。
- 涉及会议、访谈、课堂等场景时，建议在录音前提醒用户遵守当地录音告知与隐私规定。

## 11. 竞品矩阵

竞品观察的目的不是复制功能，而是判断哪些能力已经成为行业基础设施，哪些能力还能形成差异化。当前录音纪要 / AI 听记市场已经从“语音转文字”进入“会议结果自动化”阶段，单纯具备转写、摘要、导出能力不再足以形成竞争优势。

| 产品 | 核心定位 | 主要强项 | 对本产品的启发 |
|---|---|---|---|
| 夸克录音纪要 / AI 听记 | 夸克体系内的录音、导入、转写、总结、导出工具 | 网盘文件导入、移动端轻量入口、Word / PDF 导出、公开 / 加密链接分享 | 不只还原录音机体验，要把音视频沉淀为可检索、可导出、可分享的文件资产 |
| 讯飞听见 | 多入口的音频内容处理工作台 | 实时录音、外部来源导入、AI 热词库、重点标记 / 批注、语篇规整、播客转写、批量管理、硬件联动 | 借鉴“录音前配置、录音中标记、录音后整理”的完整链路；悬浮字幕、播客、硬件放到 P2 验证 |
| 飞书妙记 | 企业协作场景下的音视频转文字与会议知识沉淀 | 逐字稿搜索、翻译、在线评论、@ 同事、智能会议纪要与待办 | 会议纪要不只是个人文本，应能进入团队知识库和协作链路 |
| 钉钉 AI 听记 | 企业协同场景下的 AI 记录方式 | 智能章节纪要、待办提取、图文摘要、行业场景模板、发言人识别 | 借鉴“场景模板 + 待办闭环”，让纪要直接服务执行 |
| 腾讯会议元宝纪要 / AI 小助手 | 会议平台原生 AI 纪要 | 实时总结、会议待办、发言人高亮、会议氛围识别、多角色纪要视角 | 借鉴“会中 catch-up”和“按角色生成纪要”，降低错过关键信息的成本 |
| Otter | 跨会议 AI Meeting Agent | 实时转写、自动摘要、action items、跨工具集成、自动入会 | 借鉴“跨会议任务中心”，把多个会议里的待办统一管理 |
| Fireflies | 面向团队的会议自动化和 CRM / 工作流集成 | 自动参会、定制摘要、action items、会议搜索、CRM / Slack / 项目工具同步 | 借鉴“纪要自动流入工作流”，避免会议结束后人工搬运 |
| Granola | 面向高频会议用户的 AI notepad | 不以 bot 身份入会，结合用户手写要点与后台转写，降低会议打扰 | 借鉴“低打扰、用户掌控感”，避免 AI 过度替用户决定什么重要 |
| Notta | 多语言转写与会议记录工具 | 多语言转写、翻译、跨设备同步、摘要与可视化交付物 | 借鉴“多语言 + 多格式交付”，但需控制 MVP 范围 |
| Microsoft Teams / Zoom AI Companion | 会议平台内建 AI recap | 主持人控制、会后摘要、推荐任务、章节、发言人时间线、邮件分发 | 借鉴“权限、主持人控制、参会人可见范围、会后分发”的严谨设计 |

竞品结论：

1. 转写、摘要、章节、关键词、导出已经是基础能力，不应作为核心差异化叙事。
2. 企业级竞品强在协作和权限，会议平台竞品强在实时上下文，独立工具强在跨平台自动化。
3. 讯飞听见的启发是，录音纪要不能只做会后整理，还要在录音前提供热词等识别配置，在录音中提供标记、批注、图片等人工信号。
4. 本产品更适合避开企业平台正面战场，优先建立“本地优先、可信溯源、录音中信号、行动闭环”的差异化。
5. 如果只复刻夸克现有能力，产品会被定义为“另一个录音纪要工具”；如果把可信和执行闭环做深，才可能形成独立价值。

## 12. 差异化策略

建议产品从“功能复刻”转向“可信录音纪要工作流”：

> 面向重视隐私和准确性的个人与小团队，把录音、转写、复核、纪要、待办沉淀成一条可信工作流。

### 12.1 主目标用户

优先服务以下两类用户：

1. 高频会议 / 访谈用户：产品经理、销售、咨询、研究、HR、记者等，需要把长音频快速整理成可复核的文字资产。
2. 重视隐私的个人和小团队：不希望所有录音默认上传云端，但又需要 AI 帮助整理会议结论和待办。

暂不优先服务：

- 大型企业全员协同平台。
- 完整 CRM / 项目管理系统用户。
- 只需要简单语音备忘的轻量用户。
- 强依赖会议平台自动入会的重度远程会议团队。

### 12.2 四个竞争抓手

1. 本地优先
   默认本地录音、本地转写、本地存储；云端导入、分享、同步作为用户显式选择。用户价值是隐私感和控制感。

2. 可验证 AI
   每条摘要、章节、关键词、待办都能回跳到原文段落和音频时间码。用户不需要相信 AI，只需要快速验证 AI。

3. 行动闭环
   会议结束后自动产出“决策、待办、负责人、截止时间、风险、待确认问题”。纪要不是终点，执行才是终点。

4. 录音中人工信号
   热词、重点标记、批注和图片不只是附属工具，而是 AI 判断“什么重要”的证据。用户在会中越轻量地表达重点，会后纪要越准确、越省复核成本。

### 12.3 明确不做

- 不优先做企业级全员协作平台。
- 不优先做复杂 CRM / 项目管理集成。
- 不优先做全渠道会议 bot 自动参会。
- 不把公开链接分享作为默认路径，默认私密。
- 不用“更智能”作为无法验收的卖点，必须落到可验证的产品行为。

### 12.4 12 个月理想态

```text
当前状态                         本阶段目标                         12 个月理想态
基础录音 + 转写           ->     可信纪要闭环                ->      私密会议记忆系统
本地任务列表                     转写、摘要、播放回溯                 跨录音搜索、待办追踪
单条记录管理                     摘要溯源、低置信度提示               决策沉淀、个人知识库
会后被动整理                     热词、标记、批注辅助 AI              录音前/中/后完整工作流
```

理想态不是“多一个录音 App”，而是用户可以放心把会议、访谈、课堂、灵感记录交给它沉淀，并能在数周后追问“上次谁答应了什么、依据在哪段录音”。

## 13. AI 质量验收标准

AI 能力必须可验证、可复核、可回滚。不能把“AI 生成，仅供参考”当作免责文案后就结束设计。

| 能力 | 验收标准 | 失败处理 |
|---|---|---|
| 原文转写 | 普通中文会议可读，段落不断裂，空音频不生成假文本 | 展示“未检测到有效语音”，允许重试或保留录音 |
| 说话人区分 | 多人内容必须展示 speaker label、时间码、置信度 | 低置信度标记为“疑似发言人”，允许手动改名 |
| 摘要 | 每条摘要必须能回跳到至少一个原文时间段 | 无来源的摘要不展示为正式纪要 |
| 章节 | 章节按时间顺序生成，点击可跳转播放 | 章节过少、过密或缺少标题时允许重新生成 |
| 关键词 | 关键词点击后能定位相关段落 | 删除关键词后同步影响展示和导出 |
| 热词库 | 热词在转写结果中命中或被用于候选纠错，用户能看到当前使用的热词集合 | 热词未生效时不应虚假标记命中，可提示用户检查语言或发音 |
| 重点标记 / 批注 | 标记、批注必须绑定时间码，并可辅助生成摘要、待办或疑问清单；P2 图片遵循同一时间线规则 | 转写失败时仍保留时间线信号，不丢失用户会中记录 |
| 语篇规整 | 规整稿保留原文含义，并可回跳到来源段落或时间码 | 发现新增事实、数字或承诺时，回滚到原文并提示重新生成 |
| 待办 | 待办需包含动作、对象、负责人、时间；缺项则标记待确认 | 不完整待办进入“待确认”区，不混入正式待办 |
| 翻译 | 明确原文语言、目标语言、是否双语显示 | 翻译失败保留原文，不覆盖原文 |
| 导出 | 导出内容必须来自当前保存版本 | 导出失败给出重试和本地保存路径 |
| 分享 | 分享前确认公开范围、有效期、密码、撤销入口 | 分享失败不生成半可用链接 |

### 13.1 AI 输出展示规则

- AI 生成内容统一标记“AI 生成，可编辑，建议复核”。
- 低置信度片段要可见，不允许静默混入正式纪要。
- 摘要、章节、关键词、待办都应保留来源片段 id 或时间范围。
- 语篇规整只能生成阅读友好的派生稿，不能覆盖原始转写稿。
- 录音中标记、批注和 P2 图片应在摘要、待办和导出中有明确开关，避免用户无意分享现场私密信息。
- 用户编辑后，导出和分享必须使用编辑后的版本。
- 删除录音时，同步删除转写、摘要、导出缓存和分享链接。

### 13.2 异常与边界样例

| 场景 | 预期行为 |
|---|---|
| 录音为空或几乎全是静音 | 不生成假摘要，提示“未检测到有效语音” |
| 噪音过大 | 展示低质量提示，并允许用户保留录音、重试或删除 |
| 语言不支持 | 在提交转写前提示，或转写失败后给出明确原因 |
| AI 摘要无法找到原文依据 | 该条摘要进入“待复核”或不展示 |
| 录音中标记后转写失败 | 保留标记和批注时间线，允许用户复听或重新转写；P2 图片同样保留 |
| 语篇规整与原文事实不一致 | 标记为待复核，不覆盖原文，允许一键回滚 |
| 重复点击 AI 转写 | 复用已有任务，不创建重复任务 |
| 转写中删除录音 | 取消任务，并清理部分结果 |
| 分享链接已过期 | 访问方看到过期提示，创建方可重新生成链接 |

## 14. MVP / P1 / P2 版本切线

此前版本的 P0 范围仍偏大，容易把第一版做成完整云产品。建议按“可信闭环优先，平台扩展后置”的原则重新切线。

### P0：可信录音纪要闭环

第一版只解决一个问题：用户录完或导入音频后，能得到一份可复核、可编辑、可导出的可信纪要。

- 开始录音。
- 本地音频导入。
- 明确音频导入格式、最大时长、最大文件体积和失败原因。
- 底部主导航：记录 / 知识 / 我的；知识和我的在 P0 可为基础壳或空态。
- 统一记录列表：待转写、转写中、已转写、失败。
- 列表内“AI转写 / 已转写 / 示例笔记”状态。
- 我的 Tab 基础壳：登录入口、通用设置、隐私与数据、帮助反馈；会员 / VIP / 额度可先以占位态存在。
- 重复触发转写时复用已有任务或明确提示。
- 原文转写：时间码、段落、低置信度提示。
- 基础摘要：整体摘要 + 结构化要点。
- 播放回溯：点击文本跳转音频。
- 手动编辑标题和转写文本。
- 导出 Markdown / TXT；PDF 可作为 P1。
- 删除录音时清理关联转写、摘要和缓存。
- 基础错误处理：权限拒绝、空音频、转写失败、文件不存在。

P0 暂不包含：

- 视频导入。
- 网盘导入。
- 系统分享导入。
- AI 热词库。
- 重点标记 / 批注 / 拍照时间线。
- 语篇规整和 AI 问答。
- 公开链接 / 加密链接分享。
- Word / PDF / 音频完整导出矩阵。
- 完整会员购买、订单、支付和额度计费体系。
- 团队协作批注。
- 多端实时同步。

### P1：高价值会议能力

- 章节速览。
- AI 热词库。
- 录音中重点标记 / 批注。
- 关键词编辑、搜索范围切换、单条纪要全文搜索、全局关键词搜索和模糊搜索。
- 发言人重命名。
- 摘要溯源。
- 语篇规整。
- 待办自动提取：先在单条纪要内展示，不默认做独立一级入口。
- 知识 Tab 基础能力：全局 / 指定记录搜索、主题聚合和收藏知识卡片。
- 我的 Tab 增值能力：会员 / VIP、转写额度、导出权益、订单或兑换入口。
- 系统分享导入。
- 批量移动 / 删除 / 重试失败任务。
- Word / PDF 导出。
- 翻译语言选择与双语显示。
- 加密链接分享。
- 分享撤销和有效期。
- 播放倍速和播放设置。

### P2：增长和协作能力

- 导入视频。
- 网盘导入。
- 拍照时间线。
- 播客 RSS 转写。
- 悬浮字幕 / 内部收音。
- 多模板纪要。
- AI 问答：支持当前记录 / 全部记录两种范围。
- 发言人声纹记忆。
- 智能硬件 / 外设导入。
- 团队批注。
- 多端同步。
- 飞书 / 钉钉 / Notion / Slack 集成。
- 知识 Tab：当前记录 / 全部记录语义搜索、AI 问答、主题整理和个人知识库。

### 14.1 版本切线原则

- P0 只做“可信完成一条录音纪要”的闭环，同时保留记录 / 知识 / 我的的导航骨架，不追全量平台能力。
- P1 做会议高频复用能力，让用户从“能用”变成“愿意长期用”。
- P2 做增长、协作和生态连接，避免第一版背上过重的完整账号权益、权限、云端和集成复杂度。
- 所有 AI 能力必须先满足第 13 章的质量验收标准，再进入正式范围。

### 14.2 文档边界

本文档不是完整研发需求全集，而是产品策略、核心功能范围和 P0 / P1 / P2 版本切线。它已经覆盖产品方向、核心用户、主要流程、功能清单、AI 质量标准、竞品启发和阶段规划，但还不足以直接作为完整开发排期输入。

当前第一阶段应按 P0 执行：只完成“录音 / 本地音频导入 -> 转写 -> 摘要 -> 回放复核 -> 编辑 -> 基础导出”的可信闭环，并保留知识空态和我的基础壳。

P1 / P2 是后续演进方向，不应默认进入第一版。尤其是待办、分享、翻译、批量管理、语篇规整、热词库、会员购买和额度计费等能力，需要在 P0 留存、转写成功率、导出使用率和复访数据达到预期后再进入详细设计。

进入研发前仍需补齐：

- 逐页面交互规格和状态图。
- 支持格式、最大时长、最大文件体积。
- 转写服务、本地 / 云端处理边界和数据存储策略。
- 权限、隐私、删除、分享撤销等安全规则。
- 会员、限免、额度和导出策略。
- 埋点、实验指标和灰度策略。
- API、数据模型、异常码和测试用例。

## 15. 风险与待确认问题

- 额度与收费：截图中 Word / PDF 为“限免”，但会员权益、免费额度、时长包价格会变化，需以线上策略为准。
- 格式范围：需确认支持的音频 / 视频格式、最大文件大小、最长时长。
- 语言范围：公开资料提到多语言识别，部分第三方资料提到中、英、粤；截图中的翻译语言列表可见英语、简体中文、繁体中文、俄语、日语、韩语、西班牙语，识别语言与翻译语言需分别确认。
- 说话人区分：需明确是转写前设置、转写后显示设置，还是可触发重新识别。
- 翻译范围：需明确支持语言、是否支持双语对照、是否可导出译文。
- 分享权限：公开链接、加密链接的访问控制、有效期修改、撤销分享需要完整定义。
- AI 可解释性：摘要、关键词、章节标题都可能出错，需要提供用户编辑和重新生成能力。
- AI 质量评估：需定义转写准确率、摘要溯源率、低置信度召回率、待办误提取率等可持续追踪指标。
- 录音中辅助信号复杂度：热词、标记、批注、图片都需要绑定时间线，否则只会增加用户负担，无法提升纪要质量。
- 外部来源导入边界：系统分享、第三方 App、相册、文件管理器的权限和文件可读性不同，需定义失败原因和可恢复路径。
- 语篇规整风险：口语整理容易改写事实，必须保留原文、来源时间码和回滚入口。
- 悬浮字幕 / 内部收音限制：这类能力高度依赖系统权限和平台政策，适合 P2 验证，不宜进入 P0/P1 主链路。
- 本地优先边界：需明确哪些处理完全本地完成，哪些能力必须联网，以及用户如何感知数据是否离开设备。
- 版本取舍：若 P0 仍保留视频导入、网盘导入、公开链接分享和多格式导出，第一版交付风险会显著上升。
