# 会议语音识别 App 产品需求文档

> 从可靠录音与离线转写，演进为可追溯、可协作、可执行的会议智能产品

- 版本：v1.0
- 日期：2026-07-25
- 文档状态：产品基线稿（用于范围对齐、阶段规划与验收）
- S2 范围决策：`S2-MOBILE-CORE-2026-07-25`
- 产品原则：录音优先、本地优先、来源可追溯、用户可控制、失败可恢复

## 1. 执行摘要

本产品面向需要记录、复核和推动会议结果的个人与团队。产品不以“把语音变成一段文字”为终点，而以完成“可靠采集 → 准确转写 → 证据复核 → 形成纪要 → 推动执行 → 沉淀知识”的闭环为目标。

当前项目已经形成 Android 本地录音、离线中文识别、持久队列、结构化时间戳、会议播放复核工作区，以及可配置的 DeepSeek 云端直连和结构化纪要产品闭环；时间戳生产分段契约已经真机修复，但独立听审仍是发布门禁，说话人、PC 配对、协作和知识库仍未形成生产闭环。决策 `S2-MOBILE-CORE-2026-07-25` 将移动端 S2 收敛为可靠、可读、可人工复核的会议原文闭环；决策 `S3-PRODUCTIZATION-2026-07-25` 交付云端直连和可追溯纪要第一增量，同时让说话人准入和 PC runtime 保持明确 deferred。移动端不因自动 confidence 或热词更换 Paraformer。自动 confidence、热词和高级 ITN 转入 PC，高级音频增强/AEC 与外接麦克风验收转入各自后续阶段。移动端不建设 Live VAD 或实时转写，PC Live VAD、S4 协作与知识库、S5 企业能力均使用后续独立计划。本 PRD 对每项功能同时标注目标阶段和当前状态。

**产品北极星：** 用户能够在会议结束后快速获得一份可复核、可追溯、可执行的会议记录；任何 AI 结论都能回到原始文字和音频证据。

## 2. 产品目标与原则

### 2.1 产品目标

1. 在移动设备复杂生命周期下可靠保存会议音频。
2. 提供适用于真实会议环境的可复核转写结果。
3. 将原文转化为有来源的摘要、决策、待办和风险。
4. 让会议结论进入团队协作和任务执行流程。
5. 在本地优先、用户主动授权的前提下沉淀会议知识。

### 2.2 产品原则

- **录音优先：** ASR、AI、同步失败不能导致音频丢失。
- **本地优先：** 默认本地保存和处理；上传、备份和在线 AI 必须由用户主动开启。
- **来源可追溯：** 原文、摘要、决策、待办和问答均保留来源。
- **用户可控制：** 用户能编辑、确认、撤销、删除和选择处理位置。
- **失败可恢复：** 长任务可后台执行，失败原因可理解，可重试或降级。
- **能力真实：** 资产存在不等于能力可用；UI 只展示已经接入并验证的能力。

| 场景 | 目标流程 | 主要阶段 |
| --- | --- | --- |

S1-S3 优先服务“项目周会”和“客户访谈”。两者能够共同验证长录音、多人讨论、专业词汇、结论/待办和证据回溯，但产品模板和信息密度仍然可控。

## 4. 范围与非目标

### 4.1 范围内

- Android 现场会议录音与本地导入。
- 本地离线转写、时间轴、说话人、编辑、搜索和导出。
- 有来源的 AI 纪要、决策、待办、风险和问答。
- 主动开启的同步、协作、知识库和企业治理。

### 4.2 当前非目标

- S1 不做系统音频内录、悬浮字幕或全平台会议机器人。
- S1-S2 不承诺自动执行外部任务，只生成和确认待办。
- 未完成真机和数据集验证前，不承诺“零错误”或“完全区分所有说话人”。
- 默认不上传用户会议，也不默认将会议数据用于模型训练。
- 云空间、会员额度和价格在成本/需求验证前不写死。

## 7. 核心用户流程

### 7.1 新建会议记录

1. 录音前检查权限、存储和输入设备
2. 开始录音并持续保存
3. 停止/中断时完成音频文件
4. 创建记录和转写任务
5. 后台转写并通知结果
6. 进入记录详情复核

### 7.2 导入并转写

1. 选择音频或视频
2. 校验格式、重复、时长和大小
3. 复制到受控存储并创建记录
4. 进入本地/PC/云端处理选择
5. 转写并展示进度
6. 复核、编辑和导出

### 7.3 AI 纪要与执行

1. 原文完成且可定位
2. 生成摘要、决策、待办和风险
3. 逐项展示来源
4. 用户确认负责人和截止时间
5. 发布纪要
6. 同步任务并跟踪状态

### 7.4 知识检索

1. 选择有权限的项目/客户空间
2. 输入关键词或问题
3. 检索会议、片段和派生内容
4. 返回带来源的答案
5. 回跳原文/音频
6. 标记信息有效或过期

## 11. 分阶段验收门槛

### 11.1 S0

- ./tool/dev_check.sh 全绿
- README、PRD、当前能力清单与单一运行基线一致
- 默认发布命令明确构建真实运行时
- 回归证据对应当前提交

### 11.2 S1

- 2 小时录音、10 次连续录音和异常中断真机通过
- 导入、自动转写、失败重试和永久删除闭环
- 转写在后台任务中执行，不阻塞录音页
- 功能闭环至少覆盖低端和中端 Android 真机；资源敏感能力必须在低端通过

当前执行状态（2026-07-25）：**S1 非发布功能闭环 PASS**。低端
EVA-AL10 和中端 Xiaomi M2102J2SC 已完成核心主链、资源和生命周期门禁，
真实输入遥测、低存储注入证据、统一生命周期和核心 Goo 一致性已补齐。
高端参考设备不再反向阻塞已完成的 S1 功能验收；它作为发布候选包的兼容性
门禁单独跟踪。EXP-005 仍是生产发布门禁，不影响 S1 功能完成结论。

### 11.3 S2

- 时间戳片段、播放器联动、编辑和搜索端到端通过
- 真实标点/分段与人工三态复核可用；自动 confidence 和热词不属于 Mobile Core
- TXT/Markdown/JSON/SRT/VTT 导出通过样例验证
- 核心流程无障碍检查通过

当前 Mobile Core 状态（2026-07-25，决策
`S2-MOBILE-CORE-2026-07-25`）：18 个强制门禁中 17 个 PASS；
`ASR-005-TIMESTAMP-INDEPENDENT` 仍 **BLOCKED**。生产分段在 Xiaomi
固定音频上为 5/4 段，provisional 工程 P95=182 ms，但独立 reviewer
缺失且 `releaseEligible=false`。该人工门禁当前标记为
`SKIPPED_PENDING_USER_TEST`，由用户后续测试；跳过执行不改变验收事实，
因此 **S2 Mobile Core 仍为 BLOCKED**。

原 S2 的自动 confidence、热词、高级 ITN、GTCRN/AEC 和 REC-009
外接麦克风真机验收没有变成 PASS；它们分别标记为 `DEFERRED_TO_PC`、
`DEFERRED_NOT_PASSED` 或后续高级阶段，并保留历史 BLOCKED/FAIL 证据。
即使未来 Mobile Core 通过，发布前高端设备兼容性、EXP-005 和正式发布交付
仍须单独完成；当前整体继续 **NOT RELEASE-READY**。机器范围契约见
`docs/product/s2-mobile-core-scope.json`，逐项结论见
`docs/product/s2-asr-closure-status.md` 和

### 11.4 发布候选设备兼容性

- 功能和资源验收使用低端、中端设备；两档通过后相关功能可以标记
  `FEATURE_VERIFIED`。
- 对外发布前，最终候选包必须在低端、中端、高端三档代表设备各完成一次
  核心 smoke；高端缺失时标记 `RELEASE_COMPATIBILITY_PENDING`，不得把
  已通过的功能回退为 BLOCKED。
- 设备档位按验收时目标用户群、系统版本、内存和实测资源表现划分，不沿用
  设备上市时的营销定位。

- 摘要、决策、待办、风险使用结构化证据对象

- 供应商中立边界不默认上传会议内容

当前执行状态（2026-07-26，决策
`S3-PRODUCTIZATION-2026-07-25`）：**第一增量 `PARTIAL_PASS`，完整 S3
`BLOCKED`**。DeepSeek `cloudDirect`、Android Keystore 用户密钥、逐场明确
同意、持久限额任务、自动标题建议、三层摘要、议题、决策、待办、风险、未决项、

端侧说话人保持 `DEFERRED_NO_ADMISSIBLE_CANDIDATE`：FP32 有界候选和量表

## 12. 主要风险与缓解

| 风险 | 等级 | 缓解策略 |
| --- | --- | --- |
| 录音可靠性被识别任务拖累 | 高 | 录音与离线 ASR 解耦；识别失败不影响原始录音保存。 |
| 固定样本 benchmark 过拟合 | 高 | 扩展真实会议集，按设备/噪声/语言/人数分层并做盲测。 |
| AI 纪要产生无依据结论 | 高 | 来源强制、无来源标记、发布前确认和离线评测门槛。 |
| 文档愿景被误认为已实现 | 高 | 功能矩阵持续维护当前状态、目标阶段、证据和负责人。 |
| 云端能力破坏本地优先信任 | 高 | 默认关闭、首次上传确认、处理/存储/AI 位置三维展示。 |
| 长会议导致内存、发热和耗电问题 | 中高 | 分片处理、任务调度、真机 RTF/内存/电量门槛和降级策略。 |
| 说话人识别在重叠语音中误导用户 | 中高 | 置信度和不可辨识状态；批量修正；不强行归属。 |
| 多端同步产生冲突和误删 | 中 | 版本、软删除、冲突副本、删除传播确认和恢复窗口。 |

## 14. 文档治理与追溯

- 当前状态以可运行代码、测试和真机证据为准，不以设计稿入口为准。
- 本 PRD 是产品范围、阶段和当前功能状态的人读权威来源；机器契约用于校验
  PRD 和证据是否一致，不替代 PRD 成为第二份人工状态页。
- 功能进入下一状态时，应同时更新 PRD、当前能力清单、测试和发布说明；
  不必等待整个阶段或发布门禁通过。
- 已有 PASS 证据只在相关输入变化时重跑。失效输入包括源码或依赖、模型或
  原生库、构建/签名配置、候选包哈希、权限/targetSdk、目标 OS/设备档位、
  验收标准，或者有时效要求的外部服务。输入未变化时引用既有证据，基础设施
  故障只重跑未产生有效结果的最小集合。
- 每个功能后续应补充负责人、设计链接、技术方案、测试用例和发布版本。
- AI 或模型能力必须记录模型版本、评测集、设备范围和已知限制。
