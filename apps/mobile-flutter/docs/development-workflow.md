# App 端开发流程

适用范围：`apps/mobile-flutter`。根 [AGENTS](../../../AGENTS.md) 的授权、规则发现和工作区约束继续生效。

## 开始任务

1. 从根 [AGENTS](../../../AGENTS.md) 和规则路由开始：在仓库根执行 `python3 tool/rules_for_change.py <paths>`，读取返回的规范。
2. 读取本端 [架构](architecture.md)、受影响功能与共享包合同，再确定变更范围。Android 是当前移动目标，设备、音频权限、模型与平台合同按本端实际需求选择；不要因文档或局部修复默认运行整仓资源和打包流程。
3. 依赖关系以根 workspace 和本端 [pubspec.yaml](../pubspec.yaml) 为准，保留当前工具链和项目边界，不从桌面端复制运行脚本。

## 构建与调试

- Flutter 构建、测试或代码生成前，从仓库根按 [资源与缓存规范](../../../docs/standards/build-resources.md) 执行现有缓存守卫；不要清理其他任务或全局缓存。
- 启动、控制 App、模拟器或真机，以及截图、视觉测试和设备 watcher，均须根 AGENTS 要求的本次明确视觉授权。
- 确需启动时进入本端目录，按当前目标设备及项目配置运行；平台与实际参数见 [根启动说明](../../../README.md) 和本端配置，设备结果按目标平台分别记录。

## 完成任务

按 [本端验证入口](testing-standards.md) 和根政策选择最小充分检查；共享包、协议或原生行为变化同时核对实际反向消费者。按实际路径再次运行规则路由。原设备证据、配置和未验证分支保持原范围，不因移动端通过就声称 PC 端通过。
